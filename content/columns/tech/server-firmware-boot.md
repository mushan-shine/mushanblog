> [!abstract]
> 上一期我们把服务器的硬件拆开看了一遍：CPU、内存、硬盘、网卡这些物理部件长什么样、各自干什么。但这里有个容易被忽略的反直觉事实——**给这堆硬件通电，不等于服务器就能干活了**。通电之后到操作系统真正接管之间，还隔着一大段没人替你讲清楚的过程。
>
> 本期主角就是这段过程的主导者：**BIOS/UEFI 固件**。我们顺着一条链路走一遍——电源为什么不是一插就通、CPU 复位后第一条指令从哪来、没有内存时固件怎么"借"内存活下去、自检和设备枚举都在查什么、最后又是怎么把控制权交给 bootloader、再交给操作系统内核的。

**为什么要专门讲这一段：** 硬件通电只是「有电」，离「能跑程序」还差得远——CPU 刚复位时没有操作系统、甚至没有可用内存，谁都还没准备好。固件的全部工作，就是**把一堆刚通电、还是散沙的硬件，一步步初始化、自检，组织成一台能跑操作系统的完整平台**，再把接力棒交出去。

## 开机前奏：电源为什么不是一插就通

先补一个容易漏掉的常识：一台服务器的电源输出，不是开关全有或全无，而是**分两路**——一路叫**待机电源**，一路叫**主电源**。

<figure style="margin:1.8em 0;text-align:center"><img src="/tech/server-firmware-boot/power-two-paths.svg" alt="服务器电源的两路分工" style="width:100%;display:block"></figure>

**待机电源**：只要电源线插上市电，这一路立刻就有，不受开关机键控制。它专门供给那些需要一直醒着的小部件——**BMC 就是靠它活着的**，这样才能实现远程开关机、硬件状态监控这些"服务器还没启动也能干的事"。

**主电源**：这才是给 CPU、内存、硬盘、显卡这些大件供电的。这一路默认是关着的，由一个叫 **PWR_OK / PS_ON** 的控制信号决定通不通。只有这个信号被拉动，主电源才输出，主机的大件才真正通电。

按开机键时，实际发生的是：按键发出一个"请求上电"的信号 → BMC（或主板上的电源管理逻辑）接收到 → BMC 去拉动主电源的 PS_ON 控制信号 → 主电源打开，主机大件才开始通电，CPU 才开始复位、取第一条指令。**换句话说，通电后先醒的不是 CPU，是 BMC。**

## 整期最关键的一张图：固件的九步链路

从 CPU 复位到把控制权交给 bootloader，固件走的是一条严格有序的链路，一步都跳不过去。

<figure style="margin:1.8em 0;text-align:center"><img src="/tech/server-firmware-boot/boot-pipeline.svg" alt="固件从CPU复位到交棒的九步链路" style="width:100%;display:block"></figure>

**① CPU 通电与复位。** 把 CPU 内部强制刷成一套厂商规定死的初始状态，程序计数器被定在复位向量这一个固定地址。

**② 取第一条指令。** 复位向量这个地址被硬件线路直接映射到主板上的 SPI 固件芯片——**这是硬件焐死的，CPU 复位后取的第一条指令，必然落在 BIOS/UEFI 固件里**，没有第二种可能。

**③ 无内存时最初的引导，借缓存当内存。** 此刻 DRAM 还不能用（内存需要被配置和训练才能读写）。固件先借用 CPU 缓存当临时内存，在这块极小的临时空间里做最早的芯片组基础设置。

**④ 拉起内存。** 靠着 CPU 缓存这块临时空间，固件跑内存初始化——这一步完成，主机才有了真正可用的大块内存，程序才能被搬进 DRAM。

**⑤ POST 自检。** 内存可用后做 POST 自检，检查 CPU、内存、关键设备是否正常。这是主 CPU 自己跑固件做的，自检进度码会被 BMC 独立读取并显示。

**⑥ 枚举与初始化各种设备。** 自检过关后，固件开始扫描和初始化设备，遍历 PCIe 总线把接在上面的设备（网卡、RAID 卡、GPU、各种控制器）一个个找出来初始化，这里还会执行各设备自带的固件（Option ROM）。

**⑦ 准备交接给操作系统的资料。** 硬件都摸清楚、都初始化好后，固件把这些信息整理成标准表格留给操作系统，主要是 **ACPI 表**（OS 电源管理、设备配置等信息）和 **SMBIOS 表**（内存多大、CPU 型号等）。

**⑧ 找到启动盘，加载引导程序。** 固件按照设定的启动顺序去找启动设备，找到后读取该设备上的引导程序。传统 BIOS 去启动盘最前面的 MBR 里找引导代码；UEFI 去一个专门的 EFI 系统分区（ESP）里找 `.efi` 引导文件。

**⑨ 交棒退场。** 引导程序存在硬盘上的那个 `.efi` 文件，固件把 bootloader 加载起来，把控制权交给它，由它去加载操作系统内核。至此，固件（BIOS/UEFI）的主体任务结束。

总结来讲：固件干的活就是把一堆刚通电、还是散沙的硬件，一步步初始化、自检，组织成一台能跑操作系统的完整平台，最后把接力棒交给操作系统。

## BIOS 与 UEFI：找引导程序的方式不一样

第 ⑧ 步里提到的差异值得单独摆出来看：

| | 传统 BIOS | UEFI |
|---|---|---|
| 引导代码去哪找 | 启动盘最前面的 **MBR**（主引导记录） | 专门的 **EFI 系统分区（ESP）** |
| 引导文件形式 | 一段裸机器码 | 标准的 `.efi` 可执行文件 |
| 定位方式 | 固定读盘最前 512 字节 | 按文件系统查找指定路径的 `.efi` 文件 |

## 从固件到内核：交棒的三级链条

固件把 bootloader 加载起来之后，接力棒还要再传一次，才能真正到操作系统手里。

<figure style="margin:1.8em 0;text-align:center"><img src="/tech/server-firmware-boot/handoff-chain.svg" alt="固件到bootloader到操作系统内核的三级交接" style="width:100%;display:block"></figure>

**固件（UEFI）** 住在主板芯片里，负责把硬件唤醒，在 ESP 分区里找到 `.efi` 文件并加载——它是这条链路的起点。

**bootloader** 住在硬盘里，负责把内核和 initramfs（一套临时的最小文件系统）从磁盘搬进内存，备好启动参数，再把控制权交给内核。

**操作系统内核** 是这条链路真正的目的地：接管一切、完成自我初始化、加载完整驱动。内核先用 initramfs 这个临时文件系统，从中加载关键的驱动，靠这些驱动挂载真正的根文件系统，并切换到根文件系统——切换完成后，再启动 init/systemd，拉起各项服务，系统才算完全可用。

> 「交棒」可以理解为移交 CPU 控制权，也就是接下来该执行谁的代码。

## 结语 · 承上启下

从按下开机键的那一刻，到 bootloader 把内核加载进内存、控制权彻底移交——这中间的每一步，都是被上一步的"还不能用"逼出来的：没有内存，就先借缓存；没有资料，就先自检枚举；没有 bootloader，内核自己也进不来。固件的价值，就是把这段最原始、最没有安全感的阶段扛下来，安安静静地退场。

**下一站：** 内核接过接力棒之后，会先用 initramfs 挂载真正的根文件系统，再拉起第一个用户态程序——systemd。而这只是开机而已，真正的问题才刚开始：一堆硬件要跑一堆程序、对外提供一系列服务，谁来把这堆硬件组织成好用、有序、安全的整体？这个问题的答案，就是下一期的主角——操作系统。
